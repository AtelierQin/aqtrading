    固定规则（不可临场修改）

    加仓（金字塔式，越涨越少）

    • 触发：浮盈 ≥ +8% 且 < +11.5%（加仓窗口），且未跌破 20 日均线
    • 幅度：加原持仓的 50%，单标的累计加仓 ≤ 2 次
    • 加仓后立即把全部持仓止损上移至成本价（保本）
    • 加仓后单票市值占比 ≤ 30%、组合风险敞口 ≤ 6%
    • 禁止：浮亏加仓、亏损摊平、追高加仓

    减仓（倒金字塔式，先锁利再谈趋势）

    • 浮盈 ≥ +15%：减 1/3 锁利，剩余止损上移至成本价（保本）
    • 浮盈 ≥ +25%：再减 1/3，剩余止损上移至成本价 ×1.10
    • 跌破 20 日均线且仍有浮盈：减 1/2，剩余止损回拉到成本价（均线状态在规则引擎页点「自动判断均线」由 fuyao 日线算出）
    • 峰值浮盈 ≥ +40% 后启用移动止盈：从阶段最高价回撤 8% → 清仓剩余。离场线兜底不低于成本价 ×1.25，已锁住的利润不会被回撤吃掉
    • 触及止损价：清仓 100%，不讨论、不等反弹
    • 单日跌幅 ≥ 7% 且未到止损：减 1/2，规避流动性风险

    这个工作台是什么，不是什么

    它是「执行流程」

    • 回答四件事：买多少、止损放哪、什么时候加减、什么时候必须休息
    • 把「已经决定要交易」之后的动作固定成流程，减少临场发挥
    • 数字都由你的本金与止损价推算 —— 可复算、可追溯

    它不是「选股工具」

    • 不选股、不荐股、不预测涨跌、不给买卖信号
    • 行情数据只用于「算仓位」与「算风险」，不构成投资建议
    • 它没法帮你选对票 —— 只能让你在选错时亏得更少、留在牌桌上

    三条设计主张

    决定了哪些能改、哪些不能改

    1 · 规则先于情绪

    • 能提前写下来的决定，就不留给临场判断
    • 单笔 2% 风险锁死不可改；单票上限、组合敞口、移动止盈两参数允许你调，但调宽了立刻收到告警
    • 可调的部分必须承担提示成本 —— 这是「开放」与「失控」的分界线

    2 · 先定止损，再定仓位

    • 进场价不是重点，止损价才是 —— 它定义了这笔交易错在哪里
    • 仓位由「最多能亏多少」反推，而不是由「想买多少」决定
    • 反过来做（先想买多少再去找止损）会让风险悄悄失控

    3 · 数据自己留痕

    • 持仓台账与交易日志只存本机浏览器（localStorage），不上传任何服务器
    • 纪律分靠的是记录，不是记忆 —— 人会美化自己上周的操作
    • 随时可导出 JSON 备份，数据是你的，不锁在工具里

    交易执行顺序（不可颠倒）

    颠倒任何一步，后面算出的数字都不可信
    1. 1取价　输入 6 位代码拿到当前价 —— 它只是计算基准，不是买点
    2. 2定止损　先想清楚跌到哪里证明自己判断错了。没有止损位，这笔交易不该存在
    3. 3算仓位　2% 风险预算 ÷ 每（股/份/张）风险 → 按整手取整 → 再受单票上限与组合敞口上限压缩。每一步都只会让仓位变小，不会变大
    4. 4看目标　目标价 = 第一减仓位（成本 ×1.15，由减仓规则唯一确定）。盈亏比 = 目标收益 ÷ 止损风险 ≥ 2 才算过关
    5. 5建仓并登记　写入持仓台账。已有持仓用「手工录入已有持仓」补录，巡检周期从登记日算起
    6. 6巡检　≤3 天一次。触及止损无条件执行，不等反弹、不看消息
    7. 7加减仓　按固定阈值执行，不临场改数
    8. 8复盘计分　记录纪律分与违规类型 —— 这是唯一能长期改善的环节

    退出策略

    止损 / 止盈 / 移动止盈 一张表看完

    为什么是 2%

    把单笔亏损上限压在 2%，换来的是「连续做错也不出局」。同样次数的风险放大到 10% 会直接击穿账户：

    连续亏损2% 风险剩余本金10% 风险剩余本金回本需涨
    5 次90.39%59.05%+69%
    10 次81.71%34.87%+187%
    20 次66.76%12.16%+722%
    30 次54.55%4.24%+2,259%

    结论很直白：2% 让「连错 10 次」只是难堪，10% 让「连错 10 次」变成结束。交易系统的第一任务不是赚钱，是不被淘汰。

    移动止盈

    固定档位解决「减多少」，移动止盈解决「剩下的仓位什么时候全走」。峰值 ≥ 启用线后启用：离场线 = 阶段最高价 × (1 − 回撤)，默认回撤 8%；兜底不低于成本 ×1.25，已锁利润不会被回撤吃掉。

    三个口径：

    1. 1启用　阶段最高价浮盈 ≥ 启用线（默认 +40%）。不到线就按固定档位
    2. 2离场线　阶段最高价 × (1 − 回撤比例)。峰值越高，线越高
    3. 3兜底　离场线 ≥ 成本 ×1.25。已锁的利润不允许被一根回撤线吃掉

    同一个成本 10.00，峰值不同，守住的利润完全不同：

    成本阶段最高峰值浮盈回撤 8%兜底实际离场锁定利润
    10.0013.20+32%未启用12.50按固定档位—
    10.0014.00+40%12.8812.5012.88+28.8%
    10.0016.00+60%14.7212.5014.72+47.2%
    10.0020.00+100%18.4012.5018.40+84.0%

    阶段最高价在你每次「取现价 / 保存现价」时自动抬升（只涨不跌）。所以你只需要照常更新现价，回撤线会自己往上走。

    每条原则在哪被强制执行

    每行都对应代码里一个位置
    原则落地位置怎么落
    单笔亏损 ≤ 2%风控计算锁定不可改
    止损位与止盈位由规则算出持仓台账 · 加载时止损随浮盈档位上移（建仓 → 成本 → 成本 ×1.10 → 移动止盈线）；止盈 = 减仓档位（成本 ×1.15 / ×1.25）。缺失止损在每次加载时自动补齐
    止损只能上移持仓卡片 · 按规则校准规则位高于已设位时给建议，一键校准只上移
    盈亏比 ≥ 2风控计算不达标直接红色告警
    单票 ≤ 30% · 组合敞口 ≤ 6%风控计算 · 巡检可调 5–90% / 2–30%，超限压缩仓位并告警
    加仓窗口与幅度加减仓规则+8% ~ +11.5%；加原仓位 50%；累计 ≤ 2 次
    减仓阈值与动作加减仓规则+15% / +25% 各减 1/3；破 20 日线减半（均线由 fuyao 日线自动判断）；峰值 ≥ +40% 启用移动止盈

    巡检周期 ≤ 3 天 · 单日跌 ≥ 7% 也自动化巡检超期标「待巡检」；单日急跌自动触发减半
    周 ≤ 5 笔 · 连亏 2 笔 休息交易纪律超限提示强制休息
    行情源可换、可停、可自配数据源取价顺序由注册表决定：当前使用 → 其余已启用 → 停用不发请求；配置只存本机；内置源只可停用不可删除

    边界与免责

    • 本工作台不构成投资建议。它只负责把你的规则算准、记牢、提醒到位；买卖决定与后果由你自己承担。
    • 行情来自第三方公开接口（内置腾讯主备、东方财富、同花顺 fuyao 四条），可能有延迟、缺失或错误。取不到价时页面会降级为手动填价。
    • T+1 标的的隔夜风险：当日买入当日不能卖，若当天就跌破止损也只能等次日 —— 跳空可能让实际亏损超过 2% 预算。
    • ETF / 可转债的价格精度是 0.001 元，与股票 0.01 元不同；持仓台账目前按 2 位小数存储，录入时可能被四舍五入。
    • 移动止盈依赖阶段最高价。每次取价时自动抬升，长期不巡检、不取价的账户峰值会偏低、离场线也跟着偏低 —— 移动止盈不能替代巡检。
    • API Key 写在 localStorage（明文），换设备 / 清站点数据会一起清掉，请勿在公用电脑上填写。

    技术形态与数据存放

    便于你自己排查与迁移
    项目说明
    页面形态单文件 HTML，CSS 与 JS 全部内联，无任何外部框架、字体或图表库，可离线打开
    图标与图表全部为内联 SVG 手写，未使用任何图标字体或 emoji
    数据存储纯本机：浏览器 localStorage 两个键 —— 持仓台账 wb_astock_pos_v1、交易日志 wb_astock_log_v1。不读写任何云端数据表，行情接口除外（那只是读公开报价）
    数据边界只在这台设备的这个浏览器里：换设备、换浏览器、清理站点数据都会丢，且不提供跨设备同步。要迁移就用「导出备份」拿走 JSON 快照，到另一台设备「导入恢复」。行情接口是唯一的外网请求，只用于读公开报价，不上传任何持仓数据
    行情来源腾讯主节点 qt.gtimg.cn → 备用节点 sqt.gtimg.cn → 东方财富 JSONP，三级级联，每级 5 秒超时；三级全挂时回退到本机记录的「上次成功价」
    备份方式顶部「导出备份」得到 JSON 快照；「导入恢复」可还原，导入不设条数上限
    上线验证每次改动均通过六道门禁：语法检查、纯逻辑单测、jsdom 端到端、结构与用法检查、外链与 emoji 自检
