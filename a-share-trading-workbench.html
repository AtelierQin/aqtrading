    持仓明细

    这些规则不是给你查的，是自动执行的。每张持仓卡片顶部都有一条「现在该做」，直接给出动作、股数与点位（减仓次数从交易日志自动统计，均线状态由 fuyao 日线判定）。这一页只放规则的完整口径，供你核对。

    固定规则（不可临场修改）

    加仓（金字塔式，越涨越少）

    • 触发：浮盈 ≥ +8% 且 < +11.5%（加仓窗口），且未跌破 20 日均线
    • 幅度：加原持仓的 50%，单标的累计加仓 ≤ 2 次
    • 加仓后立即把全部持仓止损上移至成本价（保本）
    • 加仓后单票市值占比 ≤ 30%、组合风险敞口 ≤ 6%
    • 禁止：浮亏加仓、亏损摊平、追高加仓

    减仓（倒金字塔式，先锁利再谈趋势）

    • 浮盈 ≥ +15%：减 1/3 锁利，剩余止损上移至成本价（保本）
    • 浮盈 ≥ +25%：再减 1/3，剩余止损上移至成本价 ×1.10
    • 跌破 20 日均线且仍有浮盈：减 1/2，剩余止损回拉到成本价（均线状态在持仓卡片上点「判断均线」由 fuyao 日线算出）
    • 峰值浮盈 ≥ +40% 后启用移动止盈：从阶段最高价回撤 8% → 清仓剩余。离场线兜底不低于成本价 ×1.25，已锁住的利润不会被回撤吃掉
    • 触及止损价：清仓 100%，不讨论、不等反弹
    • 单日跌幅 ≥ 7% 且未到止损：减 1/2，规避流动性风险

    全仓减仓计划

    按规则阈值自动推导：成本价 ×1.15 / ×1.25，股数已按 1 手取整；移动止盈线 = 阶段最高价 ×(1 − 回撤比例)

    这个工作台是什么，不是什么

    它是「执行流程」

    • 回答四件事：买多少、止损放哪、什么时候加减、什么时候必须休息
    • 把「已经决定要交易」之后的动作固定成流程，减少临场发挥
    • 数字都由你的本金与止损价推算，可复算、可追溯

    它不是「选股工具」

    • 不选股、不荐股、不预测涨跌、不给买卖信号
    • 行情数据只用于算仓位与算风险，不构成投资建议
    • 它没法帮你选对票，只能让你在选错时亏得更少、留在牌桌上

    三条设计主张

    决定了哪些能改、哪些不能改

    1 · 规则先于情绪

    • 能提前写下来的决定，就不留给临场判断
    • 单笔 2% 风险锁死不可改。它换来的是「连错 10 次仍剩 82% 本金」；同样的错按 10% 风险做只剩 35%，回本要涨 187%。交易系统的第一任务不是赚钱，是不被淘汰
    • 单票上限、组合敞口、移动止盈两参数允许调，但调宽了立刻告警 —— 可调的部分必须承担提示成本，这是「开放」与「失控」的分界

    2 · 先定止损，再定仓位

    • 进场价不是重点，止损价才是：它定义了这笔交易错在哪里
    • 仓位由「最多能亏多少」反推，而不是由「想买多少」决定
    • 反过来做会让风险悄悄失控

    3 · 数据自己留痕

    • 持仓与日志只存本机浏览器，不上传任何服务器
    • 纪律分靠的是记录，不是记忆 —— 人会美化自己上周的操作
    • 随时可导出 JSON 备份，数据不锁在工具里

    边界与技术形态

    数据落在哪、哪些不能替你规避
    项目说明
    页面形态单文件 HTML，CSS 与 JS 全部内联，无框架 / 字体 / 图表库，可离线打开
    数据存储纯本机。两个 localStorage 键：持仓台账 wb_astock_pos_v1、交易日志 wb_astock_log_v1。不读写任何云端数据表

    外网请求只有行情接口（读公开报价），不上传任何持仓数据。API Key 以明文存在 localStorage，请勿在公用电脑上填写
    行情来源腾讯主节点 → 腾讯备用节点 → 东方财富 → 同花顺 fuyao，四级级联，每级 5 秒超时；全挂时回退到本机记录的「上次成功价」，再不行降级为手动填价
    已知限制T+1 标的当日买入次日才能卖，跳空可能让实际亏损超过 2% 预算；ETF / 可转债价格精度 0.001 元，台账按 2 位小数存储；移动止盈依赖「阶段最高价」，长期不取价的账户峰值会偏低
    免责本工作台不构成投资建议。它只负责把你的规则算准、记牢、提醒到位，买卖决定与后果由你自己承担

    1.5.3更新日志页重排 + 技术说明并入设计理念2026-09-15

    • 修复：用 fuyao 作行情源时，输入股票代码不会带出中文名。fuyao 的行情快照接口只返回 thscode / ticker，不返回中文名（腾讯 / 东财都带）。适配器当时以「空名 + nameReliable=false」落库，导致回填条件永远不成立。现在补上标的检索 /api/meta/tickers/search：快照拿不到名字时自动查一次，结果按 thscode 长期缓存（名称不会变），同一只标的不重复请求
    • 三处入口都会补名：风控计算输入代码、持仓卡「取现价」、手工录入。用户手改过名称的不覆盖
    • 新增 name_e2e 端到端用例（7 项断言）：覆盖 fuyao 快照无名的场景、标的检索回填、缓存命中、以及手改名不被覆盖
    • 整条链贯通了：目标 → 风格 → 整套阈值 → 每笔动作。设计时发现一件事：那六个「固定规则」常量其实全是止损宽度的固定倍数 —— 加仓 8%(1.6R) / 上界 11.5%(2.3R) / 减仓 15%(3R) / 25%(5R) / 移动止盈 40%(8R) / 回撤 8%(1.6R)，在 5% 止损下正好等于原来那组数字。也就是说整套规则只有一个自变量
    • 新增「我的策略」卡：三选一的交易风格（趋势跟随 8% / 波段 5% / 短线 3%），选完立刻推出全部阈值并列出 R 倍数换算
    • 换风格 = 全站重算：建仓页的默认止损幅度（5% → 8%）、持仓卡上的加仓 / 减仓触发价、移动止盈线、减仓计划清单、最低盈亏比，全部跟着变。已建立的持仓不自动改止损，需要时用卡片上的「按规则校准」
    • 单笔可以偏离风格：手工改过止损幅度后打标记，风格切换不再覆盖；点「重置」回到风格默认
    • 「固定规则」卡改为动态渲染，并补一张「以上阈值从哪来」说明推导来源
    • 新增 style/derive 测试组（18 条断言，含「三种风格都保持同一组 R 倍数」的不变量）—— 内置测试 91 → 109 条
    • 把规则变成自动执行的，而不是需要你翻页查的。此前要知道一只持仓该做什么，得去「加减仓规则」页：选标的 → 选均线状态 → 选加仓次数 → 点「生成建议」，六步才出一个结论。现在每张持仓卡片顶部直接显示「现在该做」，含动作 + 股数 + 执行价
    • 规则的两个输入都改成自动取：加仓次数从交易日志里该标的的「加仓」记录条数统计；均线状态由每张卡上的「判断均线」按 fuyao 日线判定并写回持仓（未判定时按「未跌破」处理，不误触发破线减半）
    • 删除「规则引擎」卡。它的功能已全部落到持仓卡片上，且不再需要手工输入。加减仓规则页只留「固定规则」口径 + 「全仓减仓计划」清单
    • 「今天要处理」补上「可加仓」这一类。此前浮盈到 +8% 进入加仓窗口的标的最该动作，却什么都不显示；现在与减仓、触损一起进待办
    • 新增 均线状态 持仓字段：按需由日线写入，写回后结论立即按真实均线重算
    • 新增「目标」页，补上链条的起点。此前这个工具从「算这一笔买多少」开始，没有目标也没有策略 —— 是一台计算器，不是一套系统。现在声明「本金 / 年内目标 / 可承受回撤 / 想扛住几次连亏」，风控约束由它推导出来
    • 2% 不再是写死的常量，而是算出来的结果：单笔风险 = 1 − (1 − 可承受回撤)^(1/连亏次数)。默认「15% 回撤 ÷ 8 次连亏」正好推出 2.01%，与原先那个写死的 2% 吻合 —— 区别在于现在它有推导过程，改目标它就跟着动
    • 组合敞口同理：单笔风险 × 最多同时持仓数 = 「所有持仓同日触损」时亏掉的比例（2.01% × 3 = 6.03%）
